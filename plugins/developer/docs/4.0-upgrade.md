# Upgrading the fleet to 4.0

A checklist for the machine owner, run once after 4.0.0 is installed. Steps marked **GO** change something outside the repo (Linear, GitHub, the registry) and wait for the owner's explicit go. Everything else is read-only or a dry run. Nothing here deletes anything on its own: the last section is a list for the owner to remove by hand.

Run the commands from the plugin's `skills/fleet/scripts` directory (`$F` below), with the Orchestrator's own shell (the Linear key is never given to agents).

## 1. Migrate the claim labels
1. Dry run: `$F/linear.sh migrate --dry-run`. Read what it would rename or create; it writes nothing.
2. **GO:** `$F/linear.sh migrate`.

## 2. Prove the Linear writes, then turn them on
Claims write to Linear only when `linear_writes` says so; the default is off.
1. Set `linear_writes = "test:FT"` in `config.toml` (writes allowed on the FT test team only).
2. On an FT issue run the full cycle: claim, heartbeat, a takeover attempt that must be refused, release. Check each step in Linear.
3. **GO:** set `linear_writes = "on"`.

## 3. Close stale escalations
Escalations that were open under 3.6.1 stay open until someone resolves them, so `status` starts noisy.
1. Dry run: `$F/registry.sh escalations --close-stale --note "closed at 4.0 upgrade" --dry-run` (lists what would close).
2. **GO:** run it without `--dry-run`.

## 4. Clear `pr` on merged rows
A live row keeps its `pr` after the PR merges until `next`/`reassign` clears it (for example `build-dev364/lead` still holds #42).
1. List live rows with a `pr`: `$F/registry.sh list --live | jq -r '.[] | select(.pr) | "\(.name) \(.pr)"'`.
2. For each, check with `gh pr view <url> --json state`. For a MERGED one: `$F/registry.sh set <name> pr=`.
3. **GO** for any row that is not obviously merged.

## 5. Release labels left by old issues (DEV-311, DEV-336)
1. Read the labels still on https://linear.app/devpies/issue/DEV-311 and https://linear.app/devpies/issue/DEV-336 (read only).
2. **GO:** release them with `$F/linear.sh release DEV-311` and `$F/linear.sh release DEV-336`.

## 6. Rulesets on default branches
**GO (owner applies):** on each repo agents push to, add a ruleset for the default branch: pull request required, force pushes blocked. The agents' own rules (no pushes to the default branch, `--force-with-lease` only) are a guardrail; the ruleset is the real stop.

## 7. Drop `machine_legacy_label`
1. Read check: `$F/linear.sh legacy-labels`. It lists issues still carrying an old machine label.
2. If it lists none: remove `machine_legacy_label` from `config.toml`.
3. If some remain: leave the key and file a follow-up issue naming them.

## 8. Check the new permission setup
`bypassPermissions` is refused at boot. Agents start in `permission_mode` (default `auto`). Allow `git push --force-with-lease origin fleet/*` in the permission rules your agents run under.

## 9. What 4.0 makes redundant
Remove by hand once the steps above are done. Sources: the two instruction inventories (the Mac 1 report `fleet-4.0-instruction-inventory-mac1.md` and the Mac 2 comment on DEV-368 of 19 Oct 05:10Z). Machine-, user- and company-specific items stay where they are.

### User-level hooks
- The `PreToolUse` hook that blocks edits under `.github/workflows/`: it contradicts the house rule that agents may change CI in a PR (flagged at planning time). Remove it.
- Any hook that blocks agents, or the Orchestrator, from quoting an install command: replaced by the Bash guard and `installs` in `config.toml`. Remove it.

### Workspace `CLAUDE.md`: fleet sections now in the house rules (`rules/house.md`) or the skill
- Run exactly the named verification command; show before and after. Never trust another agent's report; re-run the proof.
- Planners only plan; "go with your recommendation" approves the plan only.
- Nobody merges but the merger; never merge branches into each other. Agents write only inside their own repo.
- Escalate only when the lead asks; check for a duplicate first. Use "Blocked by" relations.
- Reports: 15 lines or fewer, verdict first, one PASS/FAIL/UNVERIFIED line per item tied to the head SHA, evidence in `reports/<ticket>-<role>.md`.
- herdr, not cmux; a pane that fails to spawn: retry once.
- "Don't re-prompt a Done row" (now: a lead keeps its workers until its own done; `next` restarts everyone).
- Agents may change CI in the PR; no AI attribution in commits or PRs.
- Cluster safety, generic part (only the declared cluster; `kind create` needs `--context`): now the team environment. The cluster names stay private.
